Packing a directory tree into a ZIP archive

Name a directory and everything under it goes in, at every depth: an entry for each directory, then its files. .ZIP chooses the format; .LZH or .PMA would choose the others.

Listing an LZH archive made on a modern computer

lha on a modern computer packs with -lh7- and -lh6- (64 KB and 32 KB windows), which the older MSX extractors cannot open. UNKAGO reads them, keeping the window in mapper memory. /L lists without extracting: the packed and original sizes, the method, the date and the path.

Writing a PMA archive

PMA is the format of PMarc and PMARC2. KAGO packs it with -pm2-, and PMEXT extracts the archive it writes. Unlike PMARC2, KAGO records each file’s real date and its exact size.

Extracting a ZIP archive into another directory

/D: extracts somewhere else, and creates the destination if it is missing. Long names that do not fit MSX-DOS’s 8.3 form are shortened the way Windows shortens them for MS-DOS, and the line says so. Before writing anything, UNKAGO checks that everything fits on the disk and in memory.

Opening a self-extracting PMA file

Many MSX programs were distributed as self-extracting PMA files, .COM programs that unpack themselves. UNKAGO reads the archive inside without running it, and leaves out the extractor it carries. This is PMEXT222.COM, the distribution of PMEXT 2.22.

Adding files to an LZH archive

With /A, KAGO adds to an archive that exists, in any of the three formats. A file whose path is already in the archive replaces the old member; the others are copied byte for byte. The new archive is written beside the old one first, so if anything goes wrong the old one is left as it was.

Extracting some members only

Names after the archive choose what to list or extract. * and ? work as wildcards across the whole path, and a directory’s name chooses everything under it. A name that matches nothing is reported at the end.

Files that already exist

UNKAGO never replaces a file unless asked: it skips it, and says so. /O overwrites.

Packing with less memory

KAGO uses the mapper memory that is free when it runs. With less than it needs for full strength (80 KB for ZIP), it says so and asks before writing anything; packing with less makes the archive a little larger, and just as valid. /Y answers yes without asking, for batch files.

Not enough disk space

Before writing anything, UNKAGO adds up the space the members will take, in whole clusters, and compares it with the free space on the destination. If it does not fit, nothing is written. Choosing some members only, or another disk, solves it.

One format chosen by switch

An archive whose name does not end in .ZIP, .LZH, .LHA or .PMA gets its format from /F:. UNKAGO needs no switch: it recognises the format by itself, whatever the name.

The usage, on the MSX

/?, or the tool’s name alone, prints the usage.
